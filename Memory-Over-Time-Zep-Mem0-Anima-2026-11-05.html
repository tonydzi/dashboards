Memory over time: one object, many events

How Graphiti (Zep's open core), Mem0 and our plain-file fact history keep the full story of a thing that changes. Measured on the hub on 5 November 2026. Built for conversations with the Zep, Mem0 and Anima Labs teams.

3 / 3Our fact history: timeline, late fact, retraction
2 / 3Graphiti temporal core with a perfect judge: retraction leaves the room empty
old + new coexistMem0 open source 2.2.1: no closing of the old fact in our test
not testedZep Cloud, Mem0 Platform temporal features, Anima Connectome on this scenario
The question in plain words. A hotel room changes guests many times. A good memory must answer three things: who is in the room now, who was in it on 7 October, and what happens when a record turns out to be wrong. Most "memory" demos only show the first question. Zep's founder argues that plain retrieval keeps both the old and the new location of a user and makes the model guess. We agree with that diagnosis, and we wanted to see how much machinery it takes to fix it.

Why Graphiti fails S3. Graphiti has no "withdraw" operation. When a new edge closes an old one, it writes the end date into the old edge itself. If the new edge later turns out to be wrong and is deleted, the old edge stays closed, so nothing is true "now". Our design never stores the end date. It derives the end date at read time from whatever newer facts are still live, so withdrawing a fact automatically reopens the previous one. A code review on 3 November showed why this matters for us: computing the end date at write time produced two live facts when two machines wrote at once.
Fairness note. In S1 and S2 Graphiti was given a perfect judge: every earlier edge of the same relation was offered as a contradiction candidate. In production an LLM picks the candidates, and a public bug report describes that judge retiring unrelated facts. So the Graphiti row is its best case. Zep's managed service may handle withdrawal through a new episode that the LLM interprets; we did not test that path.

6. Our approach in one picture

assert room-402 guest "Ivanov" --valid-at 2026-10-05 --reason checkin --source pms
  → one JSON line; nothing is overwritten, no end date is written

read "who was in room-402 on 2026-10-07"
  → gather every line from every machine, sort by valid date,
    a fact is live until the next live fact on the same attribute
  → Ivanov, 5 Oct to 9 Oct, closed by "checkout"

retract <id> --reason "operator error"
  → one more line; the previous fact becomes current again on read

Four ideas carry it: append-only lines, the end date derived on read, a reason and source on every fact, and merge across machines at read time. Tests: 30 checks green, including deliberately broken copies that must fail.

8. Method and limits

  • One synthetic object with five facts. This tests mechanics, not quality at scale.
  • Graphiti: version 0.31.2, embedded Kuzu, upstream _apply_temporal_invalidation, oracle candidates, no LLM. A deliberately broken run that skips invalidation fails S1, S2 and S3, so the test can turn red.
  • Mem0: open-source 2.2.1, local Qwen3-4B as extractor, five episodes, 3 November. A small local model is not the vendor's production extractor.
  • Retrieval table: frozen corpus, SHA256 recorded, rerun independently by two agents on 3 November.
  • Nothing here measures Zep Cloud, Mem0 Platform or Anima's production stack.
