🧩 Единая система планирования ДО → ПОСЛЕ · 2026-07-18

Как 4 разрозненных реестра склеиваются в один организм. Источник: два DR — DR26-07-16-HUB-06 (публичный роадмап) + DR26-07-17-FLEE-01 (воронка/бэклог).

1 · Что было ДО → что станет ПОСЛЕ

ДО — 4 разрезанных списка

  • alpha-backlog, improvement-backlog, реестр задач, ROADMAP — 4 раздельных ручных файла, не связаны
  • Промоут = копипаст между файлами → дрейф, разные ID, потеря истории
  • Роадмап набивается руками, расходится с реальностью; Ship-log вручную
  • Жёлтые гипотезы гниют без замера — болото
  • Битые/обрезанные строки (H04) проходят незамеченными
  • Идеи, гипотезы, задачи, релизы — свалены одинаковыми строками
  • Публичный роадмап = отдельный ручной список, формат ad-hoc
  • Метрики потока нет — сколько идей доходит до отгрузки, неизвестно

ПОСЛЕ — один поток, много видов

  • Одна карточка на элемент (ставка): стабильный ID + стадия. 4 списка = авто-генерируемые виды
  • Промоут = команда перехода на той же карточке; история пишется сама
  • Роадмап + Ship-log генерируются из карточек, руками не трогать → не дрейфуют
  • Жёлтые: лимит замеров + aging + expiry → жёлтый = сигнал, не болото
  • Схема-валидатор ловит битые строки на входе
  • Ставка ≠ задача: воронку считаем по ставкам, задачи — их дети
  • Публичный роадмап = отфильтрованное окно на карточки, формат Hybrid-Trust
  • Метрики: throughput, конверсия по воротам, lead-time, aging

2 · Как всё СКЛЕЕНО в один организм

ВНУТРИ (движок — DR FLEE-01) НАРУЖУ (витрина — DR HUB-06) одна карточка-ставка публичный роадмап IDEA ─G1─ HYPOTHESIS ─G2─ COMMITTED ─G3─ SHIPPED North Star → Now / Next / Later (эпики) │ │ → «Передумали» → Ship-log (пруф) └ задача └ задачи (дети, 1:N) ▲ │ генерируется, руками не трогать └──────────────► ЕДИНЫЙ ИСТОЧНИК ────────────────────┘ (карточки в /ops/items) из ОДНИХ карточек рисуются САМИ: alpha-backlog · improvement-backlog · task-registry · ROADMAP · Ship-log

Два DR — не два проекта, а две половины одного: FLEE-01 даёт движок (как элемент живёт внутри), HUB-06 даёт кожу (как это показать наружу, чтобы верили). Скилл /roadmap держит витрину по формату HUB-06. Отдельная сессия-сборка собирает движок по плану. Внутренняя воронка кормит публичный роадмап автоматически — ноль ручного дубля.

3 · Витрина: формат роадмапа, которому верят DR HUB-06 · 10 кейсов

Шаблон Hybrid-Trust:
North Star → Now / Next / Later (только эпики, 10-20 пунктов, не 70 задач) → «Передумали» (лог отменённого) → Ship-log (датировано + ссылки: commit/релиз/демо/dev-log)

Поля пункта: Title-как-проблема · Status · Confidence H/M/L (вместо дат) · Почему важно · Owner: Human/AI/Shared · Proof target · Links · Last moved.

3 убийцы доверия:
  • Обещанные даты — Tauri проехал «early 2024»→окт, потом убрал даты. → Confidence-ярлыки, не кварталы.
  • Тихие удаления — хуже задержек (GitHub: «неуважение»). → двигать в «Передумали» с 1 честной фразой.
  • Зомби «in progress», что не закрываются никогда.

Каденс: конец сессии 3 мин · неделя 20 мин («что сдвинулось») · месяц 15 мин уборки. Обновлять, когда работа сдвинулась — не отдельной админкой.

4 · Движок: механика воронки DR FLEE-01

IDEA идея под гейтом  →  HYPOTHESIS ставка, готовность = ЦИФРА  →  COMMITTED работа, готовность = ФАКТ  →  SHIPPED отгружено с пруфом

ГейтПереходЧто нужно, чтобы пройти
G1idea → hypothesisпроблема · гипотеза «если X → метрика Y» · baseline или задача его добыть · порог успеха · owner · срок → авто-создаётся задача замера
G2hypothesis → committedevidence-вердикт (supported/rejected) И shape (appetite · acceptance · свободная capacity) → ставит только оператор
G3committed → shippedacceptance пройден · артефакт deployed · ship_ref · release_note → авто-рендер роадмапа + Ship-log

Ставка ≠ задача: идея/гипотеза/ставка — объект решения (4 стадии); задача — объект исполнения, ребёнок ставки (1:N). Воронку считаем по ставкам, не задачам.

5 · Как чинятся 4 шва, что ты назвал

Воскресный сливпромоут = формальный переход (замерить/отложить/дубль/в-знание/выкинуть), приземляется в реальное состояние — не «галочка»
Дрейф роадмапароадмап + Ship-log = генерируемые, редактировать нельзя; release_note = обязательное поле отгрузки
Жёлтые замерылимит 2 активных замера · 7д тишины = warning · 30 = авто-в-архив; «supported», не «доказано»
Битая строка H04схема-валидатор: строка без обязательных полей не проходит гейт
Сборка → отдельная сессия (чип «Собрать единую планировочную воронку»), shadow-first, 4 фазы. Ф0-2 безопасны, 🔴 Ф3 (замена файлов) — по твоему GO.
Витрина → находки HUB-06 уходят в скилл /roadmap отдельной задачей.
Метрика потока → считать по shipped-ставкам: throughput, конверсия ворот, lead-time (median+p85), aging.
