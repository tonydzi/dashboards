🐛 Корень проблемы №1 — 28 копий Telegram-MCP

28 одинаковых процессов telegram-mcp\main.py = 5.4 ГБ впустую. Каждой сессии/переподключению нужен ОДИН, а их наплодилось 28 — старые не умирают.

Уборщик Telegram MCP Janitor отработал в 08:14 «успешно» (код 0), но 28 дублей на месте — он чистит только «сироты» с мёртвым родителем, а эти висят на живой старой сессии. То есть уборщик не лечит класс — это и есть корень.

26 из 28 — от вчерашней сессии (спавнились с 06.07 19:44). Их можно освободить сразу → +5.2 ГБ, обратимо (MCP переподключится сам при надобности).

✅ План очистки — по силе эффекта

1. Убить 26 дублей Telegram-MCP → +5.2 ГБ сразу, обратимо. Могу сделать в один клик.
2. Закрыть старую 31-часовую сессию Claude (PID 79740, простаивает — 267 сек CPU за 31 ч) → освободит гору node/conhost/cmd. Решаешь ты.
3. Закрыть лишние окна Chrome (73 процесса = 15 ГБ) → до +10 ГБ. Твоё действие.
4. Починить корень: научить Telegram MCP Janitor схлопывать дубли в рамках сессии, а не только сироты — чтобы 28 копий не наросли снова.
5. Убрать 5 программ из автозагрузки (Roblox, Discord, OneDrive, Adobe, Edge).
6. Перенести 6 фоновых задач на хаб — после сверки, что хаб их уже тянет.
